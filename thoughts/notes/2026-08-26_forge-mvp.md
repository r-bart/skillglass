# Forge MVP implementation lessons

## Durable operations include durable postconditions

Filesystem commit is not the end of an install/update transaction. Provenance and update-base metadata needed after a restart must be encoded durably in the plan and replayed idempotently after recovery and rescan.

## Revalidate immediately before replacement

A preview-time hash and an early precondition check do not close the race before `rename`. The engine must compare the live destination with `expectedBefore` after entering `applying` and immediately before replacement.

## Content hashes are not installation identities

Snapshot identity must combine installation identity and content hash. Identical bytes in two scopes are distinct installed observations and need independent edit/recovery histories.

## Adapter semantics must reach the query layer

Implementing `resolveScope` and `describeBinding` is insufficient if storage and UI infer their own inheritance. Persist the adapter result and render its evidence, including unsupported and conflict states.

## Native packaging order is part of correctness

Under a `type: module` package, a CommonJS Electron main bundle needs a `.cjs` entrypoint. On macOS, fuse mutation and nested framework signatures require a final deep ad-hoc seal in `postPackage`; signing earlier can pass static checks yet fail at dyld runtime.

## Watcher readiness and UI refresh are observable behavior

Approval must not finish until the native watcher is ready, or the first external edit can be missed. Reconciliation must refresh both inventory rows and the selected inspector, while findings remain visible to the user.

## Background refresh must preserve transient operation state

Replacing the inspector with a loading placeholder during watcher reconciliation unmounts its editor and conflict dialog. Keep the last evidenced detail mounted during a background refresh so an external-change event cannot erase an operation result.

## Portable source identity needs a filesystem generation

Device and inode are insufficient on Linux because an inode can be reused immediately after replacement. Persist the source object's creation generation at nanosecond precision when available, while accepting older provenance that predates the field.

## Linux package metadata is not inferred from a scoped npm name

DEB/RPM makers otherwise look for `@forge/desktop` instead of the packaged `Forge` executable. Set package name, product name, binary, categories, and honest pre-license metadata explicitly; keep publication blocked until the owner selects `LICENSE`.

## POSIX modes must not leak into Windows storage setup

Forge hardens its private database and recovery directory with `0700`/`0600` only on POSIX. Windows uses the ACLs of Electron's per-user application-data directory; calling `chmod` there is neither the security mechanism nor a portable prerequisite.
